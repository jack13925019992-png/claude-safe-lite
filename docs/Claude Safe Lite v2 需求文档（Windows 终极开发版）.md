# Claude Safe Lite v2 初始架构需求基线文档

> **历史基线说明**：本文档为 v2 初始研发阶段的技术架构基线规范。项目在此基线之上已进一步升级实装了 **云端 Ed25519 一机一码授权体系**、**MSIX 桌面端兼容** 与 **macOS (Apple Silicon + Intel) 跨平台原生支持**；最新双端特性、安装与发版指南请以根目录 `README.md` 及 `docs/Claude Safe Lite v2 最终交付报告.md` 为准。

## 0. 给开发 AI 的硬性工作规则

1. **构建配置红线**：**严禁修改** `Cargo.toml` 中的 `lto = "thin"`、`codegen-units = 4`、`cdylib` 配置；严禁改回 fat LTO（MinGW/GNU 工具链下会触发 `ld returned 53`）。
2. **沿用打包脚本**：**保留并沿用** `build-release.cmd`（固定 PATH、构建日志落盘、内存监控）。
3. **验证与打包策略**：开发期仅使用 `cargo check` / `cargo test` 验证；完整 release 打包只在最后执行一次（目标开发机 12GB 内存，链接阶段需预留 4GB+ 可用内存）。
4. **依赖克制原则**：新增任何 Rust crate 前，须在报告中列出「名称 + 用途 + 是否已在 v1 缓存」；优先复用 v1 已有依赖（如 Tauri 自带的 `tokio`），严禁引入重量级或与 GNU 工具链不兼容的依赖。
5. **工具链约束**：全程基于 **Windows 11 + MinGW (GNU)** 工具链；涉及 Windows API 调用（如 DPAPI、Job Object、注册表读取）时，须确认 `windows` / `windows-sys` crate 在 GNU 目标（`x86_64-pc-windows-gnu`）下可正常编译链接。
6. **路径与进程安全**：路径一律使用 `PathBuf` / `OsString`，严禁假设路径为纯 ASCII（Windows 用户名可能包含中文或空格）；启动子进程一律使用 `Command::arg()` 传参，严禁手动拼接命令行字符串。
7. **敏感信息脱敏红线**：**任何日志、界面、错误提示、崩溃报告中严禁出现代理密码明文**；代理用户名在日志中仅显示前 2 位 + `***`（不足 2 位显示 `***`）。
8. **里程碑推进**：严格按第 12 节里程碑顺序交付，每个里程碑结束时必须保证 `cargo check`（及对应单元测试）通过。
9. **UI 风格继承**：保持 v1 视觉基调——深色主题、核心「五盏灯」状态展示区不变，在其基础上清晰扩展新功能区。

## 1. 项目背景与 v2 核心目标

v1 是基于 Tauri 2 + React + TypeScript 的 Windows 桌面工具，已验证开发模式与 release 打包可用，提供「代理五项检测 + 安全启动浏览器访问 Claude」能力。

**v2（Windows 版）核心目标**：

1. **修复 v1 实测遗留 Bug**（带认证 SOCKS5 检测全红、浏览器报 `ERR_SOCKS_CONNECTION_FAILED`）；
2. **引入本地代理转发器（Forwarder）**：彻底解决 Chromium 内核不支持 SOCKS5 用户名密码认证的硬限制，并统一检测流量与业务流量链路；
3. **浏览器引擎升级**：由 Edge 切换为 **Brave → Chrome** 自动探测与隔离启动；
4. **新增安全模式与泄露自动熔断（Kill Switch / Fail-Safe）**：后台持续监测 IP/DNS 泄露与上游掉线，异常时秒级断流、强杀安全浏览器并托盘告警，杜绝直连裸奔；
5. **合并原完整版核心功能**：多套代理配置与 DPAPI 加密存储、启动 Claude Code (CLI) / Claude 桌面端、分类脱敏日志、环境重置、系统托盘驻留；
6. **打磨表单校验与友好报错体验**。

## 2. 继承的已验证事实（v2 必须保留）

- **技术栈**：Tauri 2 + React + TypeScript（前端）+ Rust（后端），目标系统 Windows 11 x64（依赖系统自带 WebView2）。
- **五项检测及联动**：①代理连接 → ②出口IP国家 → ③IP风险评分 → ④Claude可访问 → ⑤DNS泄露；①失败则后续四项置为「待定」。IP 查询接口、风险评分接口及判定阈值沿用 v1 已验证实现，不擅自更换。
- **真实上游代理特征**：带用户名/密码认证的静态住宅/静态 IP SOCKS5 代理（`host:port` + 账号密码，密码可能包含 `@ : / # %` 等特殊字符）。
- **Chromium 硬限制**：Brave / Chrome 的 `--proxy-server` 参数不支持 SOCKS5 用户名密码认证。
- **无授权体系**：不做授权页、不做姓名/手机/授权码验证。

## 3. 总体架构与状态机

### 3.1 模块架构

```text
[React 前端 (深色主题 + 五盏灯)]
        │  Tauri invoke / event
        ▼
[Tauri Rust 后端]
  ├── ProxyStore        多套代理配置 + 原子持久化 + Windows DPAPI 加密
  ├── Forwarder         本地回环转发器 (127.0.0.1:0, 引用计数, SOCKS5 + HTTP CONNECT 嗅探)
  ├── Checker           五项检测引擎 (所有检测流量强制经由 Forwarder)
  ├── BrowserLauncher   Brave/Chrome 探测 + 独立 Profile + Win32 Job Object 进程树管控
  ├── Watchdog          [新增] 安全模式后台巡检 + 上游掉线联动 + 泄露自动熔断器 (Fail-Safe)
  ├── TrayManager       [新增] 系统托盘图标、状态菜单、Windows 原生告警通知
  ├── ToolLauncher      Claude Code (CLI) / Claude 桌面客户端启动器
  └── Logger            分类日志 (app / check / launch), 强制脱敏, 5MB 轮转
```

### 3.2 流量链路

```text
安全浏览器 (Brave/Chrome) ──[无认证 SOCKS5]──┐
Claude Code (CLI)         ──[HTTP CONNECT]──┼──▶ 127.0.0.1:随机端口 (Forwarder) ──[RFC1929 认证 SOCKS5]──▶ 上游代理 ──▶ 目标站点
五项检测 / 安全巡检        ──[无认证 SOCKS5]──┘
```

> **核心设计决定**：无论上游代理是否开启认证，**所有流量一律经过本地 Forwarder**。优势：单一代码路径、检测与实际使用完全同源、域名强制透传至上游解析防 DNS 泄露、支持一键熔断断流。

### 3.3 安全模式与熔断状态机

```text
[IDLE 空闲]
    │ 点击「启动安全浏览器」→ 预检通过（记录基线出口 IP）
    ▼
[RUNNING 安全运行中] ◀──── 每 30~60 秒巡检正常 ────┐
    │                                              │
    ├── 正常关闭浏览器 ──▶ 释放 Forwarder 引用 ──▶ [IDLE 空闲]
    │
    ├── 检测到以下任一事件（安全模式开启时）：
    │     a) 出口 IP 偏离代理基线 / 发生直连泄露
    │     b) DNS 泄露（走本地 DNS 而非代理）
    │     c) 上游代理掉线（Forwarder 探测或连续建连失败）
    ▼
[TRIPPED 已熔断（锁定态）]
    │ 自动原子执行：
    │   1. 暂停/关闭 Forwarder（立即切断所有现有与新建连接）
    │   2. 通过 Job Object 强制终止安全浏览器整个进程树
    │   3. 发送系统托盘弹窗告警 + 主界面醒目红条提示
    │   4. 写入熔断日志
    │
    │ 解除条件：禁止直接重启浏览器；用户必须点击「重新检测」且关键项全绿
    ▼
[IDLE 空闲（已解锁）]
```

## 4. P0 核心需求（必须 100% 达标）

### 4.1 本地转发器（Forwarder）

- **监听绑定**：严格监听 `127.0.0.1:0`（仅本地回环，严禁 `0.0.0.0`，避免 Windows 防火墙弹窗与局域网暴露），绑定成功后读取系统分配的随机端口。
- **下游协议（客户端侧）**：
  - **SOCKS5**：仅接受「无认证」方法（`0x00`）；支持 `CONNECT`（`0x01`）；地址类型支持 IPv4（`0x01`）、域名（`0x03`）、IPv6（`0x04`）；`BIND`（`0x02`）与 `UDP ASSOCIATE`（`0x03`）明确返回 `0x07`（不支持的命令）。
  - **域名透传铁律**：收到域名类型（`0x03`）时，**必须原样透传给上游代理，严禁在本地做 DNS 解析**。
  - **同端口协议嗅探（P1，供 Claude Code 使用）**：读取首字节，若为 `0x05` 走 SOCKS5 分支；否则按 HTTP 代理 `CONNECT host:port HTTP/1.1` 解析处理（收到非 `CONNECT` 请求返回 `405 Method Not Allowed`），解析出目标 `host:port` 后同样以域名类型透传给上游 SOCKS5。
- **上游协议（代理服务器侧）**：
  - TCP 连接超时 **10 秒**。
  - 方法协商同时提议 `0x00`（无认证）与 `0x02`（用户名/密码认证，仅在配置开启认证时）；若上游选择 `0x02`，严格按 **RFC 1929** 发送认证报文（**长度字节必须按 UTF-8 字节长度 `as_bytes().len()` 计算，绝非字符数**，且单字段不超过 255 字节）。
  - 认证通过后发送 `CONNECT` 请求；双向数据转发使用 `tokio::io::copy_bidirectional`，单连接空闲超时 **5 分钟**。
- **错误应答与健康上报**：
  - 上游连接失败/认证失败/目标不可达时，必须向下游返回规范的 SOCKS5 应答码（`0x01`/`0x04`/`0x05` 等）或 HTTP `502 Bad Gateway`，不得让连接无限挂起。
  - **联动熔断器**：维护「连续上游握手/连接失败计数」，一旦在浏览器运行期间连续失败达到阈值（如 3 次，排除目标站点 404/拒连，仅计上游代理不可达或认证失败），立即向 `Watchdog` 发送「疑似上游掉线」信号，触发即时快速探测。
- **生命周期与熔断控制**：
  - **引用计数**：持有者包括「安全浏览器」「Claude Code 终端」「Claude 桌面端」「单次检测/巡检任务」。计数归零时自动关闭监听并释放端口。
  - **紧急暂停（熔断态）**：暴露 `trip()` 接口——立即关闭监听 Socket 并通过 `CancellationToken` 中断所有活跃连接的 `copy_bidirectional`，确保毫秒级断流。
  - **并发上限**：最大并发连接数 **512**，超限直接拒绝并记录警告日志。应用退出时强制清理所有连接与监听。

### 4.2 浏览器探测、启动与进程树管控

- **探测优先级**：**手动指定路径（设置页） → Brave → Chrome**（完全移除 Edge）。
- **自动探测路径**：
  1. 注册表 `App Paths`：`HKLM` 与 `HKCU` 下 `SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\brave.exe`（Chrome 查 `chrome.exe`）；
  2. Brave 常见路径：`C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe`、`C:\Program Files (x86)\...`、`%LOCALAPPDATA%\BraveSoftware\Brave-Browser\Application\brave.exe`；
  3. Chrome 常见路径同理（`Google\Chrome\Application\chrome.exe`）。
- **未找到处理**：界面友好提示并提供 Brave 官方下载链接 `https://brave.com/download/`（调用系统默认方式打开）。
- **启动参数（硬性安全防泄露参数）**：
  - `--user-data-dir=<隔离配置目录>`（见 5.3，按 `proxyId` 隔离）
  - `--proxy-server=socks5://127.0.0.1:<转发器端口>`
  - `--no-first-run`
  - `--no-default-browser-check`
  - `--disable-quic`（禁用 UDP/QUIC，防止绕过 SOCKS5 代理泄露）
  - `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`（防止 WebRTC 泄露本机真实 IP）
  - `--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1"`（兜底禁止浏览器本地 DNS 解析。**须实机验证不影响正常访问，如特定版本有副作用须在最终报告说明**）
  - 初始打开页面：`https://claude.ai`
- **进程树隔离与精准强杀（Windows Job Object，核心优化）**：
  - Chromium 为多进程架构，启动器进程往往瞬间退出并将任务移交子进程。因此**启动安全浏览器时，必须创建 Windows `Job Object`**，配置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，将浏览器子进程加入该 Job。
  - **存活监控**：每秒检查进程/Job 存活状态；若启动器在 3 秒内退出，通过 Job 内活跃进程数（`JobObjectBasicAccountingInformation.ActiveProcesses > 0`）结合配置目录下 `lockfile` 占用状态，精准判定安全浏览器是否仍在运行。
  - **安全熔断强杀**：触发熔断或用户点击「关闭安全浏览器」时，直接调用 `TerminateJobObject`（随后关闭句柄），**100% 彻底终止该安全浏览器的全部子进程，且绝对不会误杀用户自己打开的普通 Brave/Chrome 窗口**。
- **防重复启动**：同一 `proxyId` 配置目录已有安全浏览器运行时，禁止重复启动（Chromium 会忽略新实例的代理参数导致风险），提示「该代理配置的安全浏览器已在运行，请先关闭」。
- **退出联动**：安全浏览器退出后自动释放 Forwarder 引用、停止 Watchdog 巡检并刷新前端状态。

### 4.3 五项检测定义

所有检测流量强制经由 Forwarder 发出；单项超时 **10 秒**；灯状态：`green`（通过）/ `yellow`（警告）/ `red`（失败）/ `pending`（待定/灰）/ `checking`（检测中）。

| 编号 | 检测项 | 实现与判定标准 | 阻断级别 |
| :---: | --- | --- | --- |
| 01 | **代理连接** | 经 Forwarder 完成到上游的 TCP + SOCKS5 握手（+认证）+ 一次 CONNECT；精准区分错误类型：`无法连接` / `连接超时` / `认证失败` / `上游拒绝` | **关键项（阻断）** |
| 02 | **出口IP国家** | 经代理获取出口 IP 与归属国家/地区并展示；判定逻辑沿用 v1；同时记录该出口 IP 作为本次会话的「基线出口 IP」 | **关键项（阻断）** |
| 03 | **IP风险评分** | 沿用 v1 接口与风险阈值；评分偏低亮黄灯并展示原因 | 非关键项（警告） |
| 04 | **Claude可访问** | 经代理请求 `https://claude.ai`；2xx/3xx 为绿；403/CF 拦截页为红并展示人话解释 | **关键项（阻断）** |
| 05 | **DNS泄露** | 沿用 v1 检测方法，验证解析未走本地 ISP DNS；配合浏览器侧禁用本地解析实现双保险 | 非关键项（警告） |

- **联动规则**：01 失败时，02–05 立即置为「待定（灰）」。
- **防抖取消**：检测进行中若再次触发检测，立即通过 `CancellationToken` 取消旧任务。

### 4.4 检测、启动与熔断联动

- **自动检测时机**：应用启动（存在有效配置时）、保存/切换代理配置后、点击「重新检测」、点击「启动安全浏览器」前预检。
- **「启动安全浏览器」完整流程**：
  1. 若处于 **「已熔断（Locked）」状态** → 按钮置灰不可用，显示「安全熔断已触发，请先点击【重新检测】通过后再启动」。
  2. 若配置无效或正在检测 → 按钮置灰并显示具体原因。
  3. 点击后执行启动前预检（总超时上限 15 秒，显示实时进度）。
  4. **关键项（01、02、04）有红灯** → 阻止启动，展示人话原因与建议动作。
  5. **关键项全绿，但非关键项（03、05）有黄/红灯** → 弹出风险确认框列出具体风险，用户确认后可继续。
  6. 确认启动 → 持有 Forwarder 引用 → 启动安全浏览器（绑定 Job Object）→ 若开启「安全模式」则启动 Watchdog 后台巡检 → 启动成功后后台刷新一次状态展示。
- **次级入口「忽略检测，强制启动」**：仅在非熔断态下可用，需二次强确认弹窗，且强制启动记录写入 `launch.log`。（熔断状态下禁止绕过，必须先重检通过解锁）。

## 5. P1 核心安全与完整版合并需求

### 5.1 泄露自动熔断（Kill Switch / Fail-Safe）【新增重点】

开启「安全模式」后，在安全浏览器运行期间启用全自动后台保护，确保任何代理失效或泄露均不会导致浏览器流量走本地直连裸奔：

- **安全模式开关与配置**：
  - 主界面顶部明显位置提供 **「安全模式（泄露自动熔断）」开关**，**默认开启**，持久化至 `config.json`。
  - 设置页可配置后台巡检周期：默认 **45 秒**，支持在 **30 秒 / 45 秒 / 60 秒** 间选择。
- **双引擎实时监测（定时巡检 + 掉线即时触发）**：
  1. **定时后台巡检（每 30~60 秒）**：
     - **上游存活与出口 IP 泄露检测**：通过 Forwarder 查询当前出口 IP，与启动时记录的「基线出口 IP」（以及可选的本机直连 IP 特征）比对；若发生直连泄露、出口 IP 异常偏离代理 IP，或无法通过代理获取出口 IP，立即进入告警判定。
     - **DNS 泄露检测**：复测 DNS 出口是否走代理而非本地 DNS。
  2. **代理掉线即时联动**：
     - 浏览器运行期间，若 Forwarder 检测到上游代理连续连接/认证失败，立即唤醒 Watchdog 执行一次即时上游探测，无需干等 30~60 秒，实现秒级响应。
- **防误报策略（工程关键细节）**：
  - **明确泄露（零容忍，立即熔断）**：明确检测到出口 IP 变成直连/非代理 IP，或明确检测到 DNS 走本地泄露 → **0 延迟立即触发熔断**。
  - **网络超时/代理掉线（防瞬时抖动）**：单次探测超时或上游失败后，**3 秒内立即自动复测 1 次**；连续 2 次确认上游不可达/掉线 → **立即触发熔断**。
- **熔断自动执行链（严格顺序，原子执行）**：
  1. **暂停转发器**：调用 `Forwarder.trip()`，立即中断所有活跃隧道并拒绝新连接；
  2. **强制关闭安全浏览器**：调用 `BrowserLauncher.force_kill()`（通过 Win32 Job Object 终止整个安全浏览器进程树，绝不误杀普通浏览器）；
  3. **系统托盘弹窗告警**：推送 Windows 原生通知 / 托盘气泡弹窗：
     - IP/DNS 泄露时：`「检测到 IP/DNS 泄露，已强制关闭安全浏览器」`
     - 代理掉线时：`「代理连接已断开，为防止泄露已强制关闭安全浏览器」`
  4. **锁定并记录**：切换后端状态为 `Tripped`（推送 `circuit-breaker-state` 事件给前端显示醒目红色告警横幅），将触发原因、时间戳与脱敏详情写入 `launch.log` 与 `app.log`。
- **熔断解除规则**：
  - 熔断后进入锁定态，禁止直接重启安全浏览器。
  - **用户必须手动点击「重新检测」，待关键项（01、02、04）全部通过（且无泄露）后，系统自动解除锁定状态，方可再次启动安全浏览器**。

### 5.2 系统托盘与关闭保护（配合熔断告警）

- 引入系统托盘（Tauri 2 `tray-icon`）与系统通知（`tauri-plugin-notification`）。
- 托盘图标提示当前状态（空闲 / 安全保护中 / 已熔断），右键菜单包含：「显示主窗口」「关闭安全浏览器（仅运行时可用）」「退出程序」。
- **主窗口关闭拦截**：当安全浏览器正在运行时，用户点击窗口右上角 `×`，弹窗提供两个明确选项：
  - **「最小化到托盘（推荐）」**：继续在后台维持转发器与安全模式巡检；
  - **「彻底退出」**：明确提示「退出将同步关闭安全浏览器并停止代理转发」，确认后安全清理退出。

### 5.3 多套代理配置与安全存储

- **字段定义**：`id`（UUID）、`name`（配置名称）、`host`（域名/IPv4/IPv6）、`port`（1–65535）、`authEnabled`（bool）、`username`、`passwordEncrypted`（仅后端持有）。协议固定 SOCKS5。
- **管理操作**：新增、编辑、删除、复制、切换激活项；删除当前激活项时自动切换至列表中第一项（若为空则进入「未配置」态）。切换激活项时若安全浏览器正在运行，提示先关闭浏览器再切换。
- **快捷粘贴解析**：支持解析两种常见格式：
  - `host:port:user:pass`（注意：密码本身可能含 `:`，按前 3 个冒号切分，剩余全部归为 `pass`）
  - `socks5://user:pass@host:port`（兼容 IPv6 `[::1]:port` 及密码含 `@ : / # %` 的情况，从最后一个 `@` 切分认证区与主机区）
- **「测试连接」按钮**：在编辑表单内提供，仅执行 01 项检测，快速验证连通性与账号密码。
- **存储目录结构**（根目录：`%APPDATA%\ClaudeSafeLite\`）：
  ```text
  %APPDATA%\ClaudeSafeLite\
  ├── config.json              # 代理列表、激活项、应用设置（含 schemaVersion）
  ├── config.json.bak          # 上一次有效配置备份
  ├── logs\
  │   ├── app.log              # 应用与熔断日志
  │   ├── check.log            # 五项检测与巡检日志
  │   └── launch.log           # 浏览器/工具启动与退出日志
  └── profiles\
      └── <proxyId>\           # 每套代理独占浏览器用户目录（隔离 Cookie 与 Claude 登录态）
  ```
- **持久化与加密安全**：
  - `config.json` 写入采用「写临时文件 → 备份旧文件为 `.bak` → 原子重命名替换」；启动读取损坏时自动回退 `.bak` 并提示用户。
  - **密码加密**：调用 Windows **DPAPI**（`CryptProtectData`，`CRYPTPROTECT_UI_FORBIDDEN`，当前用户作用域）加密后转 Base64 存盘；**DPAPI 调用失败时报错并拒绝保存，严禁降级为明文存储**。
  - **前端零明文持有**：下发给前端的代理对象不包含密码字段，仅返回 `hasPassword: bool`；编辑时密码框为空表示「保持原密码不变」。

### 5.4 日志查看系统

- 分类标签页：**检测日志**、**启动日志**、**应用日志**；界面内展示最近 500 行，支持刷新、一键复制、导出 `.txt`/`.log` 文件、清空当前分类。
- 轮转策略：单文件上限 **5MB**，滚动保留最近 **3 份**（`.1` `.2` `.3`）。
- 全量脱敏：底层 Logger 写入前统一过滤密码及脱敏用户名。

### 5.5 重置环境

- 弹窗提供多选框：
  - `[✓]` 清理全部浏览器配置目录（提示：将退出所有代理下的 Claude 登录态）
  - `[✓]` 清理全部日志
  - `[ ]` 清除全部代理配置（**默认不勾选**）
  - `[ ]` 恢复默认设置（浏览器路径、安全模式间隔等）
- 安全拦截：若安全浏览器正在运行，拒绝执行并提示先关闭；执行前须二次确认，结果记入 `app.log`。

### 5.6 启动 Claude Code（CLI）

- 检测环境：通过 `where claude` 检测是否安装；未安装时给出清晰安装指引，不自动替用户安装。
- 终端启动：新开独立终端窗口（优先 Windows Terminal `wt`，不可用则回退 `cmd /k`），工作目录由用户选择（默认用户主目录 `%USERPROFILE%`）。
- 代理注入：通过 `Command::env()` 注入（严禁拼命令行）：
  - `HTTP_PROXY=http://127.0.0.1:<转发器端口>`
  - `HTTPS_PROXY=http://127.0.0.1:<转发器端口>`
  - `NO_PROXY=localhost,127.0.0.1`
  - （依赖 4.1 的同端口 HTTP CONNECT 协议嗅探能力）
- 生命周期：持有 Forwarder 引用，终端退出后尽力释放引用。

### 5.7 启动 Claude 桌面客户端（尽力而为）

- 路径探测：`%LOCALAPPDATA%\AnthropicClaude\app-*\claude.exe`（按语义版本号取最新目录）；未找到则友好提示。
- 参数注入：`--proxy-server=socks5://127.0.0.1:<转发器端口>`。
- 冲突检测：若检测到 `claude.exe` 已在运行，提示「Claude 桌面端已在运行，请先彻底退出（含托盘）后再通过本工具启动」。
- MSIX/Store 兼容说明：若因商店版安装形态导致无法传参，明确提示「当前安装方式不支持代理参数」，不得静默失败或假装成功。本项不阻塞 v2 核心验收。

### 5.8 一键打包发布

- 沿用 `build-release.cmd` 一键构建；产物位于 `src-tauri\target\release\`（独立绿色版 `.exe` 及原有 bundle 安装包），双击即用、无黑框终端；不新增需在线拉取外部打包工具链的目标。

## 6. P2 体验优化与报错友好化

### 6.1 代理配置表单

- 新建时输入框留空，`127.0.0.1` / `1080` 仅作灰色 `placeholder`，不作为实际值。
- 未配置代理时主界面不自动跑检测，提示「请先添加并保存真实代理配置」。
- 实时校验：主机非空且为合法域名/IPv4/IPv6；端口为 1–65535 整数；开启认证后用户名必填（新建时密码必填，编辑时留空沿用旧密码）；密码框支持明文显示/隐藏切换。

### 6.2 报错友好化规范

所有报错统一采用 **「人话原因 + 建议动作 + 折叠技术细节」** 结构：

| 场景 | 界面展示文案（人话 + 建议） |
| --- | --- |
| 无法连接上游 | 代理连不上 → 请检查代理地址、端口是否正确，以及上游服务是否在线 |
| 认证失败 | 代理账号或密码被拒绝 → 请核对用户名与密码（注意大小写与特殊字符） |
| 连接超时 | 代理响应超时 → 可能是网络波动或节点繁忙，请稍后重试或更换节点 |
| Claude 返回 403 / 拦截页 | 当前出口 IP 可能被识别为机房/高风险 IP，遭 Claude 拦截，建议更换静态住宅 IP |
| IP 风险分偏低 | 当前出口 IP 风评偏低，存在封号/风控隐患，建议更换更纯净的静态 IP |
| 未找到浏览器 | 未检测到 Brave 或 Chrome → 请点击下载安装 Brave，或在设置中手动指定路径 |
| 配置目录被占用 | 该代理配置的安全浏览器已在运行，请先关闭后再试 |
| 转发器端口绑定失败 | 本地回环端口绑定失败（可能被安全软件拦截），请重试或检查杀软放行 |
| **触发 IP/DNS 泄露熔断** | **检测到 IP/DNS 泄露，已强制关闭安全浏览器并停止转发 → 请检查本地网络/代理状态，点击「重新检测」通过后再启动** |
| **触发代理掉线熔断** | **代理连接中途断开，为防流量直连裸奔已关闭浏览器 → 请确认代理节点恢复后，点击「重新检测」解锁** |

### 6.3 底部状态栏（轻量可见）

界面底部常驻精简状态条，实时显示：
- 转发器状态（运行中 `127.0.0.1:<port>` · 当前连接数 `N` / 已停止 / 已熔断）
- 安全模式巡检倒计时或上次巡检时间（如「安全巡检正常 · 18秒前」）

## 7. v1 遗留 Bug 清单（必须根除）

1. **带认证 SOCKS5 检测全红（01 代理连接异常）**：
   - 根因排查点：HTTP 客户端是否开启 SOCKS 特性、是否误用本地 DNS 解析（须 `socks5h` 语义）、URL 拼接密码未做百分号编码、RFC 1929 字节长度错误。
   - **v2 根治方案**：检测流量全部经 Forwarder 发出，上游 SOCKS5 握手与 RFC 1929 认证全工程仅保留 Forwarder 一处标准实现，并用单元测试覆盖含特殊字符的账号密码。
2. **浏览器启动报 `ERR_SOCKS_CONNECTION_FAILED`**：
   - **v2 根治方案**：浏览器仅连本地无认证 Forwarder（`127.0.0.1:<port>`），认证完全由 Forwarder 代理完成。

## 11. 交付里程碑（按顺序推进）

- **M1（网络基座）**：上游 SOCKS5 客户端（含 RFC 1929 特殊字符修复）+ Forwarder（含引用计数、`trip()` 熔断断流、HTTP CONNECT 嗅探）+ 完整单元测试（本地 Mock 上游覆盖握手、认证成功/失败、特殊字符密码、域名透传、超时、熔断断流）。`cargo test` 全绿。

- **M3（安全模式与自动熔断）**：Watchdog 后台定时巡检 + Forwarder 掉线联动 + 防误报复测 + 熔断执行链（断流 → 杀进程树 → 托盘通知 → 锁定态）+ 重检解锁闭环 + 系统托盘与关闭拦截。
- **M4（配置与安全存储）**：多套代理配置 CRUD + Windows DPAPI 加密 + 原子写入与 `.bak` 回退 + 粘贴解析与表单校验。
- **M5（日志、重置与报错体系）**：分类脱敏轮转日志 + 日志查看器 + 重置环境 + 全场景人话报错文案。
- **M6（扩展工具）**：Claude Code (CLI) 与 Claude 桌面端启动器（P1）。
- **M7（打包与交付报告）**：执行 `build-release.cmd` 产出绿色版 exe 与安装包，输出最终交付报告（必须包含：新增依赖清单、与文档差异及原因、未实现项、需用户实机验证项）。

## 12. 验收标准（须用真实带认证代理实测）

1. **打包合规**：`build-release.cmd` 一键成功；双击 exe 直接运行无黑框；`Cargo.toml` 中 `lto = "thin"` 与 `codegen-units = 4` 未被篡改。
2. **五项检测**：带特殊字符密码的真实 SOCKS5 代理五项检测正常，失败项有人话解释。
3. **浏览器探测**：已装 Brave 优先启动 Brave；仅装 Chrome 启动 Chrome；均未装提示下载 Brave。
4. **正常上网与隔离**：安全浏览器正常打开 `https://claude.ai`，IP 查询页显示代理出口 IP；切换不同代理后使用各自独立 Profile，登录态互不串号。
5. **防泄露验证**：WebRTC 测试页不暴露本机真实 IP；浏览器无 QUIC 流量；DNS 泄露测试通过。
6. **转发器回收与 Fail-Closed**：关闭安全浏览器后本地转发端口被释放（`netstat` 不可见）；手动终止转发器时浏览器断网而非回退直连。
7. **泄露与掉线自动熔断（核心新增验收）**：
   - 开启安全模式并启动安全浏览器后，人为断开上游代理（或模拟 IP/DNS 泄露）；
   - 软件自动执行：**暂停转发器 → 精准强杀安全浏览器（且不误杀用户同时打开的普通 Brave/Chrome）→ 弹出系统托盘告警 → 主界面进入红条锁定态**；
   - 锁定态下无法直接启动浏览器；恢复代理并点击「重新检测」通过后，自动解锁并可正常重启。
8. **联动与防护**：关键项红灯时启动按钮置灰；强制启动需二次确认；同一配置目录已有浏览器运行时禁止重复启动并提示。
9. **持久化与安全**：多套代理重启后保留；`config.json` 中密码为 DPAPI 密文；日志、界面、通知中零密码明文。
10. **合并功能**：Claude Code / 更换代理 / 日志查看与导出 / 重置环境均正常可用（Claude 桌面端按 5.7 尽力而为口径验收）。

## 13. 已知风险与应对

- **出口 IP 质量不可控**：风险评分、Cloudflare 403 取决于上游节点本身，软件仅负责准确检测与人话解释，不做绕过。
- **Chromium 版本参数变动**：Brave/Chrome 升级可能影响 `--host-resolver-rules` 等参数行为，须随实机测试确认并在报告中说明。
- **Windows 安全软件误报**：未签名 exe 的本地端口监听或 Job Object 强杀行为偶发触发杀软拦截，代码需规范仅监听 `127.0.0.1` 且提供清晰报错提示。
- **Claude 桌面端形态差异**：Store/MSIX 版本可能忽略启动参数，已明确按「尽力而为 + 诚实提示」处理。
